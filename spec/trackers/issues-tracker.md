# Issues Tracker

Tracks bugs, blockers, design decisions, and technical debt. Add entries as they arise during implementation.

---

## Legend

| Symbol | Meaning |
| ------ | ------- |
| `[ ]`  | Open |
| `[/]`  | In progress |
| `[x]`  | Resolved |
| `[-]`  | Won't fix / Deferred |

### Priority

| Tag | Meaning |
| --- | ------- |
| 🔴 `P0` | Blocker — must fix before any progress |
| 🟠 `P1` | Critical — must fix before Phase 1 ship |
| 🟡 `P2` | Important — should fix before Phase 1 ship |
| 🟢 `P3` | Nice to have — can defer |

### Category

| Tag | Meaning |
| --- | ------- |
| `bug` | Something is broken |
| `decision` | Design decision needed |
| `debt` | Technical debt to address |
| `compat` | Compatibility / version issue |
| `perf` | Performance concern |
| `data` | Data quality / sourcing issue |
| `a11y` | Accessibility issue |

---

## How to use

- Add a single `ISSUE-` row for each distinct problem, decision, or debt item.
- Use the priority and category tags for triage. AI may propose new `ISSUE-` entries — mark `Raised By: ai-assistant` and add `triage:` notes.
- For AI-created issues, require a human owner assignment before auto-closing.

- **Problem**: Spec assumes `src/` directory (e.g., `src/app/`, `src/components/`), but the scaffolded project uses root `app/` without `src/`.

## Triage rules for AI-raised issues

- AI may create `ISSUE-` entries when CI or tests surface new failures. All AI-raised issues must include `Raised By: ai-assistant` and an autogenerated `notes` block with stack traces or CI artifact links.
- Human reviewer must assign `Owner:` and confirm `Priority:` within 24 hours before AI can take remediation actions (PR authoring or auto-branching).
- AI can suggest labels and a draft PR body but must not merge without human approval.
